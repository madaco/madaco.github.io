## 二、MAC和PHY芯片基础知识

### 1.MAC外设

在单片机中**MAC外设**是用于实现**以太网通信的核心硬件模块**，全称是**媒体访问控制器**（Media Access Controller）。它的作用是在硬件层面处理以太网数据帧的收发、校验、流量控制等底层协议，是单片机接入有线网络的关键硬件器件。

**MAC外设的核心功能如下：**

| 功能         | 说明                                                  |
| ------------ | ----------------------------------------------------- |
| **帧处理**   | **自动组装/解析以太网帧（目标MAC、源MAC、类型字段）** |
| **CRC校验**  | **硬件生成和验证帧校验序列（FCS），减少CPU负担**      |
| **流量控制** | **支持IEEE 802.3x暂停帧，防止网络拥塞**               |
| **双工模式** | **自动协商全双工/半双工模式（与PHY芯片配合）**        |
| **DMA支持**  | **直接内存访问，实现数据与内存间零距离拷贝**          |
| **硬件过滤** | **MAC地址过滤、多播/广播帧识别**                      |

### 2.MAC地址

MAC地址又称为硬件地址、物理地址，用于定义网络设备的位置。在OSI模型中，第三层网络层负责 IP地址，第二层数据链路层则负责 MAC地址。因此一个主机会有一个MAC地址，而每个网络位置会有一个专属于它的IP地址。

MAC地址长度是48bit（6字节），由16进制的数字组成，分为前24位和后24位：

- 前24位叫做组织唯一标志符（Organizationally Unique Identifier，即OUI），是由IEEE的注册管理机构给不同厂家分配的代码，区分了不同的厂家。
- 后24位是由厂家自己分配的，称为扩展标识符。同一个厂家生产的网卡中MAC地址后24位是不同的。

### 3.PHY芯片

PHY（Port Physical Layer），可称之为端口物理层，是一个对OSI模型物理层的简称。PHY芯片都大同小异，基本寄存器都是一样的，只有扩展寄存和厂商专门设置的寄存器不同。

### 4.MII和RMII

MII和RMII是**MAC外设与PHY芯片之间的硬件接口标准**，用于传输以太网数据帧。

MII英文全称是**Media Independent Interface**，RMII英文全称是**Reduced Media Independent Interface**。两者的对比如下：

| 特征         | MII                        | RMII                     | 影响                     |
| ------------ | -------------------------- | ------------------------ | ------------------------ |
| **数据宽度** | 4位（TXD[3:0]/RXD[3:0]）   | 2位（TXD[1:0]/RXD[1:0]） | RMII需要更高时钟补偿带宽 |
| **时钟信号** | 独立TX_CLK/RX_CLK（25MHz） | 公用REF_CLK（50MHz）     | RMII依赖外部精确时钟源   |
| **实际带宽** | 4bit*25MHz=100Mbps         | 2bit*50MHz=100Mbps       | 实际带宽一样             |
| **引脚数**   | 16根                       | 10根                     | RMII节省MCU引脚资源      |
| **布线难度** | 需等长控制4组数据线        | 只需2组数据线            | RMII降低硬件设计难度     |
| **典型应用** | 早期交换机/工业设备        | 现代单片机               | 嵌入式首选RMII           |

### 5.RMII的引脚定义

| 引脚名      | 定义                  |
| ----------- | --------------------- |
| **REF_CLK** | 50MHz参考时钟         |
| **TXD0**    | 发送数据位0           |
| **TXD1**    | 发送数据位1           |
| **RXD0**    | 接收数据位0           |
| **RXD1**    | 接收数据位1           |
| **CRS_DV**  | 载波侦听/接收数据有效 |
| **RX_ERR**  | 接收错误指示          |
| **TX_EN**   | 发送使能              |
| **MDIO**    | 管理数据输入/输出     |
| **MDC**     | 管理数据同步时钟      |

### 6.IEEE 802.3帧格式

MAC802.3 帧格式指的是 **IEEE 802.3 标准定义的以太网数据帧结构**，这是现代计算机网络（尤其是有线以太网）中最基础的数据传输单元。它规定了数据在数据链路层（OSI 第 2 层）的封装方式。

以下是MAC802.3帧的标准结构：

| 数据名称                                       | 数据长度（字节） | 作用                                                         |
| ---------------------------------------------- | ---------------- | ------------------------------------------------------------ |
| **前导码（Preamble）**                         | 7                | 一串交替的 10101010 比特模式，用于通知接收方"有数据帧到来"，帮助接收方进行时钟同步。 |
| **帧起始定界符（SFD，Start Frame Delimiter）** | 1                | 值为10101011。标识帧的开始，接收方检测到 SFD 后开始解析后续字段。 |
| **目的MAC地址（Destination MAC Address）**     | 6                | 目标设备的物理地址（如 00:1A:2B:3C:4D:5E）。如果是广播帧，值为 FF:FF:FF:FF:FF:FF |
| **源MAC地址（Source MAC Address）**            | 6                | 发送设备的物理地址。                                         |
| **长度/类型字段（Length/Type Field）**         | 2                | 类型（Type）： 标识上层协议类型（如 0x0800 表示 IPv4，0x86DD 表示 IPv6）。<br/>长度（Length）： 当值 ≤ 1500 时，表示数据字段的长度（单位：字节）。 |
| **数据与填充字段（Data & Padding）**           | 46~1500          | 数据 (Payload)： 上层协议传递的数据（如 IP 包）。<br/>填充 (Padding)： 若数据 < 46 字节，需填充至 46 字节（确保帧最小长度为 64 字节，防止冲突检测失败）。 |
| **帧校验序列（FCS, Frame Check Sequence）**    | 4                | 基于 CRC-32 算法计算帧的校验和                               |

参考：https://www.cnblogs.com/mrlayfolk/p/11965347.html
