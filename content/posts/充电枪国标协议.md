## 1.协议大致内容

指明了BMS与充电机之间的CAN通讯规范，充电交互逻辑。

## 2.协议内容注意点

- 充电过程电流是负值。公共场站，充电电流只能在-400A~0A，接收到这以外的充电电流应退出充电流程；私有场站，按照私有协议执行。
- 地址固定，不可修改。充电枪地址：0x56(86)；BMS地址：0xF4(244)。
- 数据信息传输采用低字节先发送的格式。
- 报文中的数据值和物理量之间的转换关系：物理量=分辨率*数据值+偏移量。
- 该国标协议中使用的是直流快充，不是交流慢充。直流充电枪使用CAN传输数据，交流充电枪使用PWM和电压状态传输数据。交流充电使用GB/T 18487.1-2023协议。

## 3.CAN报文格式

本协议中使用的是29位标识符的CAN扩展帧，每个位的分配采用SAE J1939-21:2006规定，具体标识符和数据域的格式如下图所示：

![](/images/充电枪国标协议/协议数据单元.png)

数据长度在8个字节以内和长度超过8个字节，这两种的帧ID和数据域都有所不同。

### 3.1数据长度8个字节以内

帧ID按照PDU的格式，P是优先级，EDP和DP都为0，PF是PGN的bit8-bit15，PS和SA就是充电枪或BMS的地址(0x56或0xF4)。

数据域完全按照报文格式介绍来。

**举例——充电机握手报文CHM**

![](/images/充电枪国标协议/数据长度8个字节以内-举例1.png)

```
P优先级是6，二进制就是110
EDP和DP都是0
PF直接看PGN的中间两个16进制数，即0x26
这里是充电机向车辆发的报文，目的地址PS=0xF4，源地址SA=0x56
组成起来 (000)(110)(00)(0x26)(0xF4)(0x56)  最前面的000是29位标识符补到32位的填充位
帧ID：0x1826F456
```

![](/images/充电枪国标协议/数据长度8个字节以内-举例2.png)

```
这个报文只有3个字节数据，假设报文为01 02 03
按照报文格式解析，版本号为V1.23(?是V1.2.3还是1.23或其他的存疑，文档中并没有解释清楚)
```

### 3.2数据长度超过8个字节

因为一帧数据帧最多只能传输8个字节数据，当长度超过8个时就需要利用多帧传输，多帧传输采用传输协议功能进行传输。

大致的过程就是发送方先发送一个**"请求发送"**的报文，数据域中带有这个报文的信息。接收方接收到后回复一个**"准备发送"**的报文，代表我接收到请求了，并且我准备好了，你可以发了。然后发送方开始发送多个数据帧，每个数据帧中都有帧号，让接收方知道数据组装的顺序。接收方接收到所有数据帧后，发送一个**"消息结束应答"**，代表数据我都收到了，我要结束消息应答了，你不用再发了。当发送方收到这个后会发送一帧**"放弃连接"**的报文，代表断开和接收方的连接。详情内容可以查看同目录下的文档《SAE J1939-21-中文.pdf》

**举例——车辆充电参数报文BCP**

![](/images/充电枪国标协议/数据长度超过8个字节-举例1.png)

![](/images/充电枪国标协议/数据长度超过8个字节-举例2.png)

```
传输协议-连接管理的帧ID：
P优先级是7，十六制就是111
EDP和DP都是0
PF固定为236，十六进制就是0xEC
这里是车辆向充电机发的报文，目的地址PS=0x56，源地址SA=0xF4
组成起来 (000)(111)(00)(0xEC)(0xF4)(0x56)  最前面的000是29位标识符补到32位的填充位
帧ID：0x1CECF456
```

![](/images/充电枪国标协议/数据长度超过8个字节-举例3.png)

```
传输协议-数据传送的帧ID:
这里跟传输协议-连接管理不同的地方就是PF=235，即0xEB
因此帧ID:0x1CEBF456
```

![](/images/充电枪国标协议/数据长度超过8个字节-举例4.png)

```
连接模式下的请求发送:
byte1:固定为16，十六进制0x10
byte2,3:整个消息13个字节，十六进制为0x000D，按照低字节
```

![](/images/充电枪国标协议/数据长度超过8个字节-举例5.png)

## 4.A类系统充电流程

物理连接完成->低压辅助上电->充电握手阶段->充电参数配置阶段->充电阶段->充电结束阶段

### 4.1充电握手阶段

![](/images/充电枪国标协议/充电握手阶段报文.png)

#### 4.1.1充电机握手报文(CHM)

![](/images/充电枪国标协议/充电机握手报文.png)

帧ID：0x1826F456，数据位：3个字节，代表充电机通信协议版本号

#### 4.1.2车辆握手报文(BHM)

![](/images/充电枪国标协议/车辆握手报文.png)

帧ID：0x182756F4，数据位：2个字节，绝缘检测允许的总电压值。按照转换公式，电压=0.1V*数据值+0

#### 4.1.3充电机辨识报文(CRM)

![](/images/充电枪国标协议/充电机辨识报文.png)

帧ID：0x1801F456，数据位：8个字节，辨识结果+充电机编号+充电机/充电站所在区域编码

#### 4.1.4BMS和车辆辨识报文(BRM)

![](/images/充电枪国标协议/BMS和车辆辨识报文1.png)

![](/images/充电枪国标协议/BMS和车辆辨识报文2.png)

帧ID：0x1CEC56F4，这里因为超过8个字节，需要用到SAE1939:21中的传输协议连接管理功能，优先级P=7，PF=236，转换成十六进制，就是0x1CEC56F4。

![](/images/充电枪国标协议/传输协议-连接管理.png)

因为数据位有超过8个字节，需要分多个数据帧发送。第一帧是上图中的"连接模式下的请求发送"，8个字节是一些配置参数。从第二帧开始就是实际的有效数据，每一帧的第一个字节代表包号，从1开始，其余7个字节按照报文格式要求发送。

BMS向充电枪发送"连接模式下的请求发送"后，充电枪需要回复"准备发送"，帧ID是0x1CECF456，数据位按照下图所示：
